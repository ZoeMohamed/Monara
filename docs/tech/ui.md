# UI and PWA

Owner: Erdafa. Features: F1, F2, F4, F5, F6, F7, F8, F9, F11, F12, F13, F15. Status: Draft.

## Purpose

Monara provides an English, light-only, mobile-first financial interface with HeroUI controls. The public `/demo` is an immediate sample experience; protected routes load the signed-in User's owned ledger through the Next.js backend. Demo changes stay in browser memory and reset on reload. A failed live load shows recovery rather than sample records.

## How it works

**Entry and identity (F1).** [Sign-in](../../apps/web/src/components/sign-in-screen.tsx) offers Google OAuth and a public demo in the approved landscape/card layout, with an October preview and “A little clarity. More room to live.” The protected [layout](../../apps/web/src/app/(finance)/layout.tsx) verifies the Supabase server session and supplies sanitized identity. Profile supports sign-out. The [demo layout](../../apps/web/src/app/demo/layout.tsx) supplies a synthetic guest and no financial backend calls. One [Demo indicator](../../apps/web/src/components/demo-indicator.tsx) identifies the active experience with accessible reset information. A [quick tour](../../apps/web/src/components/product-tour.tsx) observes streamed Home targets before opening its native modal. It explains confirmed totals, review, Chat and Add at every width, offers Next/Back/Skip and replays from Profile. Completion and amount visibility store display flags only.

**Presentation.** [Shared UI](../../packages/ui/src/index.ts) exports HeroUI primitives and the [light theme](../../packages/ui/src/theme.css); Nunito Sans loads locally. Desktop uses the same Home composition in a wider layout, with a floating glass sidebar and the branded lockup. [Home](../../apps/web/src/components/mobile-overview.tsx) leads with exact spending over the existing landscape, Monara's mascot head above the composer and a rounded content sheet. OYenza informs spacing and composition; the blue palette, landscape and white/cyan character remain Monara's own, with no paws or legs. It omits the redundant Overview heading and header wordmark. [Glass navigation](../../apps/web/src/components/monara-app.module.css) provides Home, History, Reports, Budgets and Add on mobile; the desktop sidebar shares its styling. A [toast](../../apps/web/src/components/session-toast.tsx) confirms saves and offers eligible demo Undo: bottom-right on desktop, above the navigation on mobile. Open modals defer the toast and its timer until closing, preserving a reachable Undo window. The Home HeroUI input accepts a typed question; Enter/Send opens Chat and sends the trimmed prompt once, while blank Send opens Chat. Home prompt shortcuts sit directly below Ask Monara inside the landscape hero in one horizontally scrollable row with scroll snap at every width; Chat shortcuts stay above its bottom composer. Chat opens from Home prompts; Profile and Notifications open from its compact header. Supported scroll timelines provide restrained parallax; reduced motion disables it. Semantic titles, labels, focus and safe-area clearance remain part of the [design conventions](../ui-design-system.md).

**Ledger and review (F4, F5).** The [snapshot adapter](../../apps/web/src/lib/finance/presentation.ts) validates and exhausts transaction/account/category/budget pages, validates the dashboard and preserves original DTOs. It fails on incomplete/repeated pages or unresolved resources. Shared decimal-string money is range-checked using `bigint` before entering the safe-integer presentation model; wider values produce an explicit recovery error, never rounding. Full transport-range editing remains **Planned**.

[Session handling](../../apps/web/src/components/use-monara-session.ts) connects live add/edit/pending-edit/confirm/exclude/delete controls to [validated operations](../../apps/web/src/lib/finance/client.ts). Account and category selectors use owned UUIDs, updates carry expected versions and creates retain request IDs. Failed drafts retain their entries; repeated submissions are blocked. A saved change followed by failed reload is reported distinctly from an unverified write. [Finance synchronization](../../apps/web/src/components/use-finance-sync.ts) refreshes selected months, ignores stale reads and serializes mutations. Loading or uncertain results block further writes until a successful refresh. The [transactions screen](../../apps/web/src/components/transactions-screen.tsx) has a “To review” toggle that shows how many pending records are waiting and opens them in the same list. Pending records keep their uncertain fields, and each one can be confirmed, edited or excluded. Confirmed income/expense records alone affect totals; excluded records remain available through the Excluded History filter. Demo Undo is record-specific and stale-safe. Durable live Undo remains **Planned** because its operation is unsupported.

[Details](../../apps/web/src/components/transaction-details.tsx) lead with the exact payment and an icon flow through the saved account, category and destination; income reverses the source/account order. Excluded records retain the same available facts with an explicit status. [Account icons](../../apps/web/src/components/account-badge.tsx) use supplied institutions and a conservative [brand lookup](../../apps/web/src/data/brand-identity.ts) of about 110 Indonesian banks, e-wallets, merchants and subscriptions to select locally bundled official artwork or a CC0 Simple Icons mark served from the app's own [`/brand-icons`](../../apps/web/src/app/brand-icons/[icon]/route.ts) route; unknown names retain neutral type glyphs/initials. Merchant rows/details share exact known company/service aliases. No substring matching or account nickname supplies an institution, and a registered bank never decorates a wallet. The [logo field](../../apps/web/src/components/brand-logo-field.tsx) in the transaction and bank/wallet forms shows the matched logo as a name is typed; Change logo opens a [search](../../apps/web/src/components/logo-search.tsx) over registered brands and the [server-side catalog](../../apps/web/src/lib/brands/catalog.ts). A chosen logo is a per-name display preference in browser storage and never edits the record. [Provenance](../../apps/web/public/brands/README.md) records unchanged colours/proportions and sources; logos never supply an account mapping. Gmail provenance remains visible and editable without changing source identity; confidence stays secondary. Home, History and Reports share [TransactionRow](../../apps/web/src/components/transaction-row.tsx).

[Navigation](../../apps/web/src/data/app-navigation.ts) and [route handling](../../apps/web/src/components/use-app-navigation.ts) provide canonical months, types, UUID detail links and history. Searches, amounts and drafts stay out of URLs. Missing records show a closeable error, and draft cancellation checks unsaved changes.

**Dashboard, Reports and recommendations (F6, F9).** [Overview models](../../apps/web/src/data/overview-model.ts) provide five recent confirmed records, a navigable Needs attention list and reproducible month facts below the hero. Pending/invalid/future-dated records are excluded from latest activity; unavailable bill coverage is not called all clear. The model and [analytics](../../apps/web/src/data/finance-analytics.ts) derive confirmed-only totals and comparisons from the complete ledger. Live category grouping and drilldowns use UUIDs, preserving separate categories with equal names; snapshot refresh resolves current labels. [Reports](../../apps/web/src/components/reports-screen.tsx) retain daily/running spending, calendar, donut, six-month bars and [spending flow](../../apps/web/src/components/spending-flow.tsx). Top places totals expenses with the same merchant/title and exposes the underlying payment rows; Biggest expenses ranks up to five distinct single confirmed payments. History and Reports share [FinancialSummary](../../apps/web/src/components/financial-summary.tsx) with exact confirmed spending/income/net, mini bars sharing the larger recorded spending/income total and a compact matched-period comparison (no target or safe-spend claim); History filters leave those monthly totals unchanged. Reports adds canonical Monthly/Yearly navigation, preserving `period=yearly&year=YYYY` through drilldowns and Back; yearly totals cover twelve actual months with annual category/payment rankings and monthly cash flow. Current-year comparisons match the prior year through the same month/day with leap-day clamping; historical years compare full years. Income and net remain exact alongside spending; net is not a stored account balance. Chart controls support pointer and Arrow/Home/End selection. Reports places a compact Daily spending calendar under the spending trend, beside Where the money went and Cash flow on desktop. Days lead with their spent amount and heat, the bold average reads “Average RpX per day”, and the selected day's payments sit below the grid as in the bill calendar. Equal-elapsed-day comparisons clamp shorter months and expose missing/future periods. Safe spending subtracts all confirmed expenses from limits, including unbudgeted categories, and shows its basis. The backend now returns reproducible savings rate, safe-to-spend, per-Budget overspend forecasts, three-month unusual flags and Budget suggestions; the live Overview surfaces actionable forecasts and flags. User-timezone acceptance and explicit suggestion acceptance UI remain **Planned**.

**Budgets, bills and Reminders (F7, F8, F12, F13).** By category offers Edit budgets: in edit mode each row opens its editor directly and an Add budget row appears inside the card. List rows on Overview, Budgets and Reports use one inset, rounded hover/pressed shape spanning the card width, and the separators beside a hovered row step aside. Live [Budget Manager](../../apps/web/src/components/budget-manager.tsx) creates, edits, pauses and deletes weekly/monthly limits with owned category IDs, create-request IDs and expected versions. Shared [period logic](../../packages/contracts/src/budgets.ts) anchors monthly budgets to the selected start/payday, clamps short months without drifting and preserves seven-day weekly cycles. Use last income is an explicit User choice. Demo budget editing is session-only. Rows first open shared [Budget details](../../apps/web/src/components/budget-details.tsx) with limit, usage/remaining, period and warning, then Edit. Usage queries include the full active interval across calendar boundaries while Reports totals stay in their selected calendar month. Progress uses explicit backend periods and exact money; equality says “At limit” and excess “Over budget”. [Banks & wallets](../../apps/web/src/components/financial-account-setup.tsx) adds bank/wallet/cash entries with explicit institution choices, including OVO, and shares them with the single transaction Account/payment-method selector. [Demo resource mapping](../../apps/web/src/data/demo-resources.ts) maps editor UUIDs to synthetic labels while retaining explicit account IDs; excluded records never affect income/spending. Profile's [Category Manager](../../apps/web/src/components/category-manager.tsx) selects existing categories and creates, edits or archives them; creation is also available from the Add budget category dropdown, so Budgets no longer carries a separate category manager. [Icon selection](../../apps/web/src/data/category-icons.ts) follows the name as it is typed (a brand's logo for an exact brand name such as Netflix, otherwise a matching symbol) until a symbol or a searched logo is chosen; the choice is saved as the category's icon. Web-only category creation validates a request UUID, derives ownership and uses an exact replay check in the [repository](../../packages/core/src/supabase-finance-repository.ts), without a new migration or unsupported Undo receipt. Edit/archive uses expected versions; archived categories leave new choices while existing records keep their references. Demo account/category changes last for the visit. Home's daily guide applies only to monthly budgets that follow the calendar month, subtracts all confirmed monthly expenses (including unbudgeted categories) and divides by days left. Payday periods show exact period remainder without a daily estimate or calendar pace needle. The demo bill calendar uses explicit next due dates. Live bill and WhatsApp link/preference operations remain unsupported; detection, preferences and scheduling/delivery remain **Planned**. The roomier [center](../../apps/web/src/components/reminders-center.tsx) opens from Notifications and separates User-created Reminders from app-generated Updates, with concise actions and visible message text, amounts and dates. Owned web list/read/archive operations store read receipts with expected-status checks; pagination ignores superseded responses and fails on repeated cursors; they do not pay bills. [Derived financial attention](../../apps/web/src/data/financial-attention.ts) also exposes one pending-review batch, current-cycle budget warnings/overruns and known due/overdue bills with Review/View actions. It resolves when current record conditions clear, deduplicates matching stored events and keeps derived acknowledgement in browser memory; it does not match a bill payment or schedule delivery. Personal reminders have free names, optional User-defined tags, explicit due dates and optional amounts and edit/done/reopen receipts in demo memory only; live persistence, automatic payment matching and scheduling remain Planned. Updates also shows demo recurring-bill proposals using the same [Track bill/Dismiss card](../../apps/web/src/components/recurring-bill-suggestion.tsx) and session callbacks as Budgets; tracking a proposal does not pay it. Live active notifications feed the dashboard; demo warnings are snapshots. The [handoff](../ui-backend-handoff.md) records acceptance gaps.

**Gmail and Chat (F2, F11).** [Gmail client](../../apps/web/src/components/gmail-connections-client.tsx) adapts owned list/connect/reconnect/disconnect, limits, callbacks and consent-return recovery. The [callback-origin helper](../../apps/web/src/lib/gmail/callback.ts) validates a configured public HTTPS tunnel, moves local development Gmail entry to that origin before sign-in and refuses localhost consent starts. It trusts configured origins rather than arbitrary forwarding headers. Local OAuth acceptance requires matching provider callbacks described in [the handoff](../ui-backend-handoff.md#local-gmail-callback-acceptance); the current local attempt lacked required configuration. Import and Sync Now remain **Planned**. The authenticated [Chat bridge](../../apps/web/src/app/api/chat/route.ts) injects server identity/credentials. The validated [client](../../apps/web/src/lib/chat/client.ts) retains bounded history/receipts and marks lost replies as possibly completed. [Route handling](../../apps/web/src/components/app-route-views.tsx) shares the mutation/recovery gate, reconciles once without replay and blocks Agent requests during pending/failed refresh. Verified receipts remain visible if their subsequent refresh fails. [Action feedback](../../apps/web/src/components/chat-action-result.tsx) limits Yes/Cancel to the latest unexpired Agent confirmation; a later user message or error closes it. Undo is unavailable. Durable turn idempotency/status and configured live-provider acceptance remain **Planned**.

**PWA (F15).** The [manifest](../../apps/web/src/app/manifest.ts), [install guidance](../../apps/web/src/components/install-app-button.tsx) and [production registration](../../apps/web/src/components/pwa-register.tsx) support installation. [Worker v7](../../apps/web/public/sw.js) caches only the static fallback, manifest, named PWA icons, SVG favicon and two public fonts. Public fetches omit credentials and reject unsafe responses; personalized HTML, framework chunks, RSC, auth and finance responses stay outside caches. Offline navigation shows a generic fallback. Physical installation and keyboard/touch acceptance remain **Planned**.

## Key decisions

- **Offer demo before consent.** Requiring OAuth before seeing value was rejected; the demo is separately labelled and never substitutes for a failed live ledger.
- **Retain review and exact values.** Automatic import confirmation and guessed/rounded fields were rejected because uncertain records must remain pending and excluded from totals.
- **Keep the picture and useful charts.** Redundant mobile headings and crowded summary cards were reduced while retaining financial context, navigation and drilldowns. Motion is progressive and respects reduced motion.
- **Keep identity and writes server-side.** Direct component database writes and client-supplied identity were rejected; the UI calls defined operations with owned resources and concurrency metadata.
- **Keep offline caching public.** Personalized app caching was rejected to prevent financial/auth state from being retained by the service worker.

## Security and risks

The [server identity boundary](../../apps/web/src/lib/supabase/server.ts) and backend repositories enforce authorization; presentation controls and UUID URLs are not ownership checks. Cookie-authenticated mutation routes verify same origin and return private/no-store responses. The UI holds no provider credentials and caches no financial records in local storage.

Live writes can succeed before a response or reload fails. Recovery performs reads without automatically replaying an uncertain Agent turn. No durable client-turn idempotency/status API exists, so a timed-out server action may complete after reconciliation. Demo Undo is not durable reversal. Remaining risks needing evidence are real-session isolation, stale/ambiguous writes, provider OAuth, duplicate-safe ingestion, Agent/backend compatibility, User-timezone accounting and phone behavior. Wider contract money fails explicitly.
