# UI and PWA

Owner: Erdafa. Features: F1, F2, F4, F5, F6, F7, F8, F9, F11, F12, F13, F15. Status: Draft.

## Purpose

Monara is an English, light-only, mobile-first finance PWA. Home leads with one spending number; History, Reports and Budgets provide detail. Blue surfaces, Nunito Sans, the landscape and mascot follow the [design system](../ui-design-system.md). HeroUI supplies controls through [packages/ui](../../packages/ui/src/index.ts); CSS and SVG compose the branded screens.

Reconciled on 16 October 2026 with the current [PRD](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.pm2pb9a5y3zd), [Action Tracker](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.5tiin0qzk1mg), [Brainstorm](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.0) and [runtime decision](../adr/0001-initial-runtime-boundaries.md). The [UI action checklist](../ui-actions-2026-10-16.md) separates tracker status, implemented source and acceptance still required. This draft awaits owner review.

## How it works

**Entry and navigation (F1).** [Sign-in](../../apps/web/src/components/sign-in-screen.tsx) offers Google OAuth and a public `/demo`. The protected [layout](../../apps/web/src/app/(finance)/layout.tsx) verifies the server session. Demo uses labelled synthetic memory state that resets on reload. [Navigation](../../apps/web/src/components/use-app-navigation.ts) preserves month, review and detail routes; financial searches and drafts stay out of URLs. Profile provides sign-out, connections and the replayable [tour](../../apps/web/src/components/product-tour.tsx).

**Ledger and review (F4, F5).** The [snapshot adapter](../../apps/web/src/lib/finance/presentation.ts) validates complete paginated records and retains DTO versions. [Session handling](../../apps/web/src/components/use-monara-session.ts) connects add/edit/delete and pending edit/confirm/reject to owned backend operations. Missing fields remain visible. Only confirmed expenses and income affect totals; transfers are excluded. [Synchronization](../../apps/web/src/components/use-finance-sync.ts) ignores stale reads, serializes writes and retains failed drafts. Uncertain outcomes require refresh. The [account manager](../../apps/web/src/components/financial-account-setup.tsx) edits bank/wallet/cash details and confirms deactivation/reactivation. Inactive accounts retain history and cannot be selected for new transactions. Edits carry expected versions; stale or uncertain results require a record refresh and reopening the editor. Demo Undo is local. Live Chat can request receipt-based Undo for supported transaction/budget actions through the [Agent tool](../../apps/agent/src/conversation/write-tools.ts) and [backend](../../packages/core/src/finance.ts); expiry, ownership and stale versions are checked there.

**Summary and budgets (F6, F7, F9).** [Home](../../apps/web/src/components/mobile-overview.tsx) shows selected-month totals, recent activity and actionable attention items. [Reports](../../apps/web/src/components/reports-screen.tsx) supports monthly/yearly charts and payment drilldowns. [Budget Manager](../../apps/web/src/components/budget-manager.tsx) uses owned categories, exact usage and weekly/monthly periods, including payday anchors. A [suggestion](../../apps/web/src/components/budget-suggestion.tsx) reads three months of confirmed history, exposes its inputs and fills the draft only after “Use suggested limit”; Save performs the write. The [category daily guide](../../apps/web/src/components/category-spending-guide.tsx) shows backend amounts, period, remaining days and calculation on expansion. An overall calendar-month guide includes unbudgeted expenses; non-calendar periods suppress that estimate. Figures describe spending, not account balances.

**Gmail (F2).** The [connection client](../../apps/web/src/components/gmail-connections-client.tsx) handles up to three mailboxes, separate consent, reconnect, disconnect, last mailbox scan and Sync now. The [screen](../../apps/web/src/components/gmail-connections-screen.tsx) labels imported/skipped/failed counts as cumulative **Import history**. Bounded reads stop on cancellation or failure; queued work and unchanged counts never imply completion. Queue/cron ingestion source exists in the [worker](../../apps/agent/src/gmail/worker.ts); provider acceptance remains outstanding.

**Chat, bills and Reminders (F8, F11, F13).** The [Chat bridge](../../apps/web/src/app/api/chat/route.ts) verifies identity and validates Agent responses. The Agent's [dashboard read tool](../../apps/agent/src/conversation/read-tools.ts) exposes validated affordability, forecasts and unusual flags with their confirmed-data basis. Each verified live reply refreshes the ledger, including Undo replies without new receipts. Failed refresh retains the reply and blocks further changes until recovery. Latest unexpired destructive confirmations offer Yes/Cancel; uncertain requests are never replayed automatically. Notifications supports owned read/archive operations; the Agent can list existing Reminders. Backend budget writes create deduplicated threshold receipts. Personal reminder editing and bill proposals are demo memory only. Persistent bill operations, preferences and scheduled delivery remain **Planned**. Unsupported bill/settings tools are absent from the Agent catalog.

**WhatsApp (F12).** The [Profile row](../../apps/web/src/components/whatsapp-link-row.tsx) uses owned [GET/POST/DELETE routes](../../apps/web/src/app/api/whatsapp/link/route.ts). Enter a number, obtain a code, then send it from that number. Codes remain in mounted memory. [Status handling](../../apps/web/src/components/use-whatsapp-link.ts) polls while pending, refreshes on return, clears expired codes and ignores stale responses. Change number edits locally; requesting a replacement and confirming Unlink are explicit writes. An uncertain mutation requires Check status before another change and is never replayed automatically. Session expiry clears private state. A confirmed backend queue/session gap still blocks unlink/relink acceptance; see Security and risks.

**PWA (F15).** The [manifest](../../apps/web/src/app/manifest.ts) defines standalone installation. The [service worker](../../apps/web/public/sw.js) allows only public icons, logos, local fonts, manifest and generic offline fallback into cache. Auth, APIs, app documents and framework chunks require the network. Offline mode shows recovery, without financial records.

## Key decisions

| Decision | Alternative considered and reason |
| --- | --- |
| HeroUI controls with branded composition | Rebuilding input/button behavior would duplicate the shared control foundation. |
| Separate demo and owned live data | Substituting examples after a failed load would misrepresent the User's ledger. |
| Read-only proposal, explicit acceptance, then Save | Automatic budget creation would violate F7's acceptance rule. |
| Generic offline fallback | Caching personalized pages would violate F15 and the runtime privacy boundary. |

## Security and risks

Identity, ownership and financial writes belong to the Next.js backend and repositories. Cookie-authenticated mutations check origin and return private/no-store responses. UI controls and UUIDs do not authorize access; provider credentials stay server-side. Shared money uses decimal strings; the current editor explicitly rejects values outside its safe-integer range rather than rounding.

**F12 blocker:** [queued conversations](../../apps/agent/src/whatsapp/session.ts) do not recheck the current verified link before Agent execution or outbound retries. An offline source reproduction ran a queued turn and sent a reply after unlink, retried an old reply after unlink, and retained two previous-number history turns after relinking. Argya must bind sessions to a link generation, clear invalidated history/work and revalidate backend operations and sends before provider acceptance. No external request was made.

Other open acceptance risks are authenticated persistence/isolation, stale writes, live OAuth/ingestion, model scenarios and phone installation/keyboard behavior. Profile currently presents UTC while Gmail scan time uses WIB; User-timezone accounting remains unaccepted. A timed-out Agent action can finish later because durable client-turn status lookup is absent.
