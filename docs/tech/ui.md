# UI and PWA

Owner: Erdafa. Features: F1, F2, F4, F5, F6, F7, F8, F9, F11, F12, F13, F15. Status: Draft.

## Purpose

Monara lets the User review financial records and inspect confirmed spending through an English, light-only HeroUI interface. The rich financial screens currently use synthetic browser state. Google sign-in is a real, separate integration; signing in does not make the displayed sample ledger a persisted personal ledger.

Reconciled on 14 October 2026 against [PRD v2.1](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.7t8u9nqsrfc), the [live Action Tracker](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.5tiin0qzk1mg), and [ADR 0001](../adr/0001-initial-runtime-boundaries.md). The tracker marks ER1–ER3/ER11 and ZO1–ZO5 Done, while ER4–ER10/ER12 remain In progress. Backend contracts, schema, Google Auth, Gmail connection APIs, financial operations, and the Agent runtime are implemented in the repository; connecting those operations to all financial screens remains **Planned**. No deployment or live-provider acceptance is established by this document.

## How it works

The [finance layout](../../apps/web/src/app/(finance)/layout.tsx) verifies the server session and supplies a sanitized profile to [MonaraApp](../../apps/web/src/components/monara-app.tsx). Its [shared session context](../../apps/web/src/components/app-session-context.tsx) owns the synthetic ledger and bill changes. Route navigation retains those changes and drafts; reload or unmount resets them. [Navigation](../../apps/web/src/data/app-navigation.ts) validates allowlisted month, type, and UUID parameters; [route handling](../../apps/web/src/components/use-app-navigation.ts) connects sheets and filters to browser history. Search text, amounts, and drafts stay out of URLs. Missing sample records show a closeable error; failed saves retain entries, and cancellation checks unsaved changes.

[Shared UI](../../packages/ui/src/index.ts) provides HeroUI controls and the [theme](../../packages/ui/src/theme.css). Nunito Sans loads locally; the [supplied SVG lockup](../../apps/web/src/components/logo.tsx) preserves its cat and wordmark. Mobile navigation uses equal Home, Transactions, Budgets, Chat, and Add items; Reports, Reminders, and Profile are in the header. Main content and Chat clear navigation by 7rem and 5.75rem respectively, plus the safe-area inset. [Design conventions](../ui-design-system.md) cover typography, flat surfaces, focus, and 44px controls.

**Identity and Gmail (F1, F2).** [Sign-in](../../apps/web/src/app/sign-in/page.tsx) uses the implemented Google OAuth routes and server identity checks; Profile displays that identity and supports sign-out. Gmail consent remains separate. [Gmail APIs](../../apps/web/src/app/api/gmail/connections/route.ts) implement owned connection lifecycle operations, but the [connection page](../../apps/web/src/app/connections/gmail/page.tsx) still renders an unavailable state. [Gmail presentation](../../apps/web/src/components/gmail-connections-screen.tsx) supports mailbox status, last sync, reconnect/disconnect, limits, progress, and counts when supplied with state/callbacks. **Planned:** wiring that presentation to provider results and import jobs; configuration and live OAuth need separate verification.

**Review and ledger (F4, F5).** [Review Queue](../../apps/web/src/components/review-queue.tsx) shows missing/low-confidence fields. The [editor](../../apps/web/src/components/transaction-editor.tsx) supports pending edits/confirmation, manual creates, and confirmed corrections; [details](../../apps/web/src/components/transaction-details.tsx) also supports deletion. Demo validation requires a positive safe whole IDR amount, type and valid date, with owned-account integration still pending. [Ledger helpers](../../apps/web/src/data/demo-ledger.ts) preserve identity/status, exclude rejected/pending/invalid records from confirmed totals, and implement record-specific stale-safe Undo. These mutations are session-only. **Planned:** adapting them to the implemented [financial APIs](../../apps/web/src/app/api/finance/operations/[operation]/route.ts), durable rejection/deduplication, concurrency responses, and action receipts.

**Overview and Reports (F6).** The [overview model](../../apps/web/src/data/overview-model.ts) derives spending, income, difference, budget attention, recent records and warnings. The [hero](../../apps/web/src/components/overview-hero.tsx) keeps exact spending over a static landscape with the simple shared mascot. The device clock changes only the greeting; the financial sample date stays labelled. There are no character tips, looping scene motion, or Pause/Play control.

[Financial visuals](../../apps/web/src/components/financial-visuals.tsx) provide daily/running spending, calendar, donut, and six-month income/expense bars; [spending flow](../../apps/web/src/components/spending-flow.tsx) connects recorded categories and merchants. All Report panels remain visible. Category/day/place payments open canonical transaction details. Pointer and Arrow/Home/End selection, visible focus, and reduced-motion handling remain. [Analytics](../../apps/web/src/data/finance-analytics.ts) compare equal elapsed days, clamp shorter previous months, and expose missing/future states. Totals use `bigint`; transfers affect neither income nor spending. **Planned:** using the implemented server aggregates and completing User-timezone behavior.

**Budgets, insights and bills (F7–F9).** [Budgets](../../apps/web/src/components/budgets-screen.tsx) retain progress bars, a small gauge, exact limits/usage, and explicit at-limit/over-budget labels. Safe-to-spend subtracts all confirmed expenses, including unbudgeted categories, from total limits; it clamps the overall remainder once and exposes shortfall and per-category inputs. The dashboard also shows income minus spending and a defined savings percentage when income exists. Budget editing, weekly-period UI, forecasts, unusual flags, and suggestions remain **Planned**; backend budget operations alone do not finish ER8/F9. Bill suggestions require confirmation; [the calendar](../../apps/web/src/components/bill-calendar.tsx) uses active bills' explicit next due dates, without generating occurrences. Detection and persistent management remain **Planned**.

**Chat, settings and Reminders (F11–F13).** [Chat](../../apps/web/src/components/chat-screen.tsx) discloses that its UI adapter is disconnected and retains failed drafts without inventing replies or changes. The merged Agent has a `/chat` endpoint; [the current UI callback](../../apps/web/src/components/app-route-views.tsx) does not call it. Profile linking/preferences remain unavailable or informational. In-app warnings are synthetic threshold/bill snapshots, not delivery history. **Planned:** the authenticated chat bridge, verified WhatsApp-link UI, saved preferences, and Reminder scheduling/delivery/deduplication.

**PWA (F15).** The [manifest](../../apps/web/src/app/manifest.ts), [installation guidance](../../apps/web/src/components/install-app-button.tsx), and [production registration](../../apps/web/src/components/pwa-register.tsx) support installation. [Worker v7](../../apps/web/public/sw.js) caches only the static fallback, manifest, named PWA icons, SVG website favicon, and two public fonts. It excludes app HTML, framework chunks, RSC, auth and financial responses. Public fetches omit credentials and reject unsafe responses; offline navigation uses the generic fallback. Website favicons remain distinct from installed PWA artwork.

## Key decisions

- **Retain human review.** Automatic confirmation was rejected because missing extraction fields must remain uncertain and pending records must not affect totals.
- **Keep sample state explicit.** Treating available backend code as completed UI integration was rejected; session-only financial mutations remain labelled while adapters are pending.
- **Keep the picture, mascot and charts.** Excess badges, textures and motion were reduced; removing useful visualizations was rejected under the User's clarified design direction. Exact amounts never count through temporary values.
- **Use routes and focused Undo.** State-only navigation and whole-ledger rollback were rejected because they break history and can overwrite newer edits.
- **Keep authorization and writes server-side.** Direct financial writes from components and personalized offline caching were rejected to preserve ownership checks and privacy.

## Security and risks

[Server identity](../../apps/web/src/lib/supabase/server.ts) and the financial service enforce backend boundaries; a URL UUID, sample account label, disabled control, or caller-supplied User ID does not authorize access. The UI holds no provider credentials or financial local-storage cache. Authenticated identity and the displayed synthetic ledger must remain clearly separate.

The [backend handoff](../ui-backend-handoff.md) records contract mapping: decimal-string money, UUID resources, nullable values, confidence units, optimistic versions and idempotency. Demo helpers are not production authorization, scheduling, or durable Undo. Live OAuth/provider configuration, cross-user isolation, duplicate-safe ingestion, ambiguous write failures, and actual phone installation/touch/keyboard require independent evidence.
