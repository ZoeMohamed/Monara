# UI and PWA

Owner: Erdafa. Features: F1, F2, F4, F5, F6, F7, F8, F9, F11, F12, F13, F15. Status: Draft.

## Purpose

Monara provides an English, light-only, mobile-first financial interface with HeroUI controls. The public `/demo` is an immediate sample experience; protected routes load the signed-in User's owned ledger through the Next.js backend. Demo changes stay in browser memory and reset on reload. A failed live load shows recovery rather than sample records.

Reconciled on 14 October 2026 against [PRD v2.1](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.7t8u9nqsrfc), the [Action Tracker](https://docs.google.com/document/d/1JPvoReZT6AZJ6YAJz6nbJk5kblqoGbj7ztX1LPn5lBE/edit?tab=t.5tiin0qzk1mg) and [ADR 0001](../adr/0001-initial-runtime-boundaries.md). The tracker marks ER1–ER3/ER11 and ZO1–ZO8 Done, ZO9 Not started, and ER4–ER10/ER12 In progress. Implemented adapters do not establish live-provider or deployed acceptance.

## How it works

**Entry and identity (F1).** [Sign-in](../../apps/web/src/components/sign-in-screen.tsx) offers Google OAuth and a public demo in the approved landscape/card layout, with an October preview and “A little clarity. More room to live.” The protected [layout](../../apps/web/src/app/(finance)/layout.tsx) verifies the Supabase server session and supplies sanitized identity. Profile supports sign-out. The [demo layout](../../apps/web/src/app/demo/layout.tsx) supplies a synthetic guest and no financial backend calls. One [Demo indicator](../../apps/web/src/components/demo-indicator.tsx) identifies the active experience with accessible reset information. A [quick tour](../../apps/web/src/components/product-tour.tsx) observes streamed Home targets before opening its native modal. It explains confirmed totals, review, Chat and Add at every width, offers Next/Back/Skip and replays from Profile. Completion and amount visibility store display flags only.

**Presentation.** [Shared UI](../../packages/ui/src/index.ts) exports HeroUI primitives and the [light theme](../../packages/ui/src/theme.css); Nunito Sans loads locally. Desktop uses the same Home composition in a wider layout, with a floating glass sidebar and the branded lockup. [Home](../../apps/web/src/components/mobile-overview.tsx) leads with exact spending over the existing landscape, Monara's mascot head above the composer and a rounded content sheet. OYenza informs spacing and composition; the blue palette, landscape and white/cyan character remain Monara's own, with no paws or legs. It omits the redundant Overview heading and header wordmark. [Glass navigation](../../apps/web/src/components/monara-app.module.css) provides Home, History, Reports, Budgets and Add on mobile; the desktop sidebar shares its styling. A [toast](../../apps/web/src/components/session-toast.tsx) confirms saves and offers Undo: bottom-right on desktop, above the navigation on mobile. Chat opens from Home prompts; Profile and Reminders open from its compact header. Supported scroll timelines provide restrained parallax; reduced motion disables it. Semantic titles, labels, focus and safe-area clearance remain part of the [design conventions](../ui-design-system.md).

**Ledger and review (F4, F5).** The [snapshot adapter](../../apps/web/src/lib/finance/presentation.ts) validates and exhausts transaction/account/category/budget pages, validates the dashboard and preserves original DTOs. It fails on incomplete/repeated pages or unresolved resources. Shared decimal-string money is range-checked using `bigint` before entering the safe-integer presentation model; wider values produce an explicit recovery error, never rounding. Full transport-range editing remains **Planned**.

[Session handling](../../apps/web/src/components/use-monara-session.ts) connects live add/edit/pending-edit/confirm/reject/delete controls to [validated operations](../../apps/web/src/lib/finance/client.ts). Account and category selectors use owned UUIDs, updates carry expected versions and creates retain request IDs. Failed drafts retain their entries; repeated submissions are blocked. A saved change followed by failed reload is reported distinctly from an unverified write. [Finance synchronization](../../apps/web/src/components/use-finance-sync.ts) refreshes selected months, ignores stale reads and serializes mutations. Loading or uncertain results block further writes until a successful refresh. [Review Queue](../../apps/web/src/components/review-queue.tsx) preserves uncertain fields and pending flags. Confirmed income/expense records alone affect totals; transfers are excluded. Demo Undo is record-specific and stale-safe. Durable live Undo remains **Planned** because its operation is unsupported.

[Navigation](../../apps/web/src/data/app-navigation.ts) and [route handling](../../apps/web/src/components/use-app-navigation.ts) provide canonical months, types, UUID detail links and history. Searches, amounts and drafts stay out of URLs. Missing records show a closeable error, and draft cancellation checks unsaved changes.

**Dashboard, Reports and recommendations (F6, F9).** [Overview models](../../apps/web/src/data/overview-model.ts) and [analytics](../../apps/web/src/data/finance-analytics.ts) derive confirmed-only totals and comparisons from the complete ledger. Live category grouping and drilldowns use UUIDs, preserving separate categories with equal names; snapshot refresh resolves current labels. [Reports](../../apps/web/src/components/reports-screen.tsx) retain daily/running spending, calendar, donut, six-month bars and [spending flow](../../apps/web/src/components/spending-flow.tsx). Chart controls support pointer and Arrow/Home/End selection. Equal-elapsed-day comparisons clamp shorter months and expose missing/future periods. Safe spending subtracts all confirmed expenses from limits, including unbudgeted categories, and shows its basis. User-timezone acceptance, overspend forecasts, unusual flags and accepted three-month budget suggestions remain **Planned**.

**Budgets, bills and Reminders (F7, F8, F12, F13).** Live [Budget Manager](../../apps/web/src/components/budget-manager.tsx) creates, edits, pauses and deletes weekly/monthly limits with owned category IDs, create-request IDs and expected versions. Progress uses explicit backend periods and exact money; equality says “At limit” and excess “Over budget”. [Financial Account setup](../../apps/web/src/components/financial-account-setup.tsx) creates bank/wallet/cash entries. Profile's [Category Manager](../../apps/web/src/components/category-manager.tsx) renames owned categories with expected versions, validates returned identity/name and reconciles dropped responses without replay. Home's “Safe to spend today” card divides total monthly limits minus all confirmed monthly expenses by the days left, with a pace bar and the category needing attention. The demo bill calendar uses explicit next due dates. Live bill and WhatsApp link/preference operations remain unsupported; detection, preferences and scheduling/delivery remain **Planned**. Live reminders come from the dashboard; demo warnings are snapshots. The [handoff](../ui-backend-handoff.md) records acceptance gaps.

**Gmail and Chat (F2, F11).** [Gmail client](../../apps/web/src/components/gmail-connections-client.tsx) adapts owned list/connect/reconnect/disconnect, limits, callbacks and consent-return recovery. Import and Sync Now remain **Planned**. The authenticated [Chat bridge](../../apps/web/src/app/api/chat/route.ts) injects server identity/credentials. The validated [client](../../apps/web/src/lib/chat/client.ts) retains bounded history/receipts and marks lost replies as possibly completed. [Route handling](../../apps/web/src/components/app-route-views.tsx) shares the mutation/recovery gate, reconciles once without replay and blocks Agent requests during pending/failed refresh. Verified receipts remain visible if their subsequent refresh fails. [Action feedback](../../apps/web/src/components/chat-action-result.tsx) limits Yes/Cancel to the latest unexpired Agent confirmation; a later user message or error closes it. Undo is unavailable. Durable turn idempotency/status and configured live-provider acceptance remain **Planned**.

**PWA (F15).** The [manifest](../../apps/web/src/app/manifest.ts), [install guidance](../../apps/web/src/components/install-app-button.tsx) and [production registration](../../apps/web/src/components/pwa-register.tsx) support installation. [Worker v7](../../apps/web/public/sw.js) caches only the static fallback, manifest, named PWA icons, SVG favicon and two public fonts. Public fetches omit credentials and reject unsafe responses; personalized HTML, framework chunks, RSC, auth and finance responses stay outside caches. Offline navigation shows a generic fallback. Physical installation and keyboard/touch acceptance remain **Planned**.

## Key decisions

- **Offer demo before consent.** Requiring OAuth before seeing value was rejected; the demo is separately labelled and never substitutes for a failed live ledger.
- **Retain review and exact values.** Automatic import confirmation and guessed/rounded fields were rejected because uncertain records must remain pending and excluded from totals.
- **Keep the picture and useful charts.** Redundant mobile headings and crowded summary cards were reduced while retaining financial context, navigation and drilldowns. Motion is progressive and respects reduced motion.
- **Keep identity and writes server-side.** Direct component database writes and client-supplied identity were rejected; the UI calls defined operations with owned resources and concurrency metadata.
- **Keep offline caching public.** Personalized app caching was rejected to prevent financial/auth state from being retained by the service worker.

## Security and risks

The [server identity boundary](../../apps/web/src/lib/supabase/server.ts) and backend repositories enforce authorization; presentation controls and UUID URLs are not ownership checks. Cookie-authenticated mutation routes verify same origin and return private/no-store responses. The UI holds no provider credentials and caches no financial records in local storage.

Live writes can succeed before a response or reload fails. Recovery performs reads without automatically replaying an uncertain Agent turn. No durable client-turn idempotency/status API exists, so a timed-out server action may complete after reconciliation. Demo Undo is not durable reversal. Remaining risks needing evidence are real-session isolation, stale/ambiguous writes, provider OAuth, duplicate-safe ingestion, Agent/backend compatibility, User-timezone accounting and phone behavior. Wider contract money fails explicitly.
